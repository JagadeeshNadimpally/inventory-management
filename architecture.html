Architecture & Technical Overview

System Architecture

The system follows a three-tier architecture with clear separation of concerns between frontend, backend, and data layers.

Technology Stack

🎨 Frontend

  • Vue 3 - Progressive JavaScript framework
  • Composition API - Modern state management
  • Vite - Fast build tool and dev server
  • Vue Router - Client-side routing
  • Axios - HTTP client
  • Port: 3000

⚙️ Backend

  • FastAPI - Modern Python web framework
  • Pydantic - Data validation & serialization
  • Uvicorn - ASGI server
  • Starlette - Web toolkit (via FastAPI)
  • CORS Middleware - Cross-origin requests
  • Port: 8001

💾 Data & Storage

  • JSON Files - Data persistence
  • In-Memory Loading - Fast access
  • Python Dict - Data structures
  • No Database - Demo system
  • Location: /server/data/
  • Auto-reload: Server restart

Key Characteristics

✓ Type-Safe: TypeScript-ready Vue 3 + Pydantic models

✓ Modern: Vite for fast development, FastAPI with async support

✓ Scalable: RESTful API design ready for database integration

Data Flow

How data moves through the system from user interaction to backend processing:

1

User Interaction

User selects filters (warehouse, category, date, status) or navigates between views via the UI.

2

Vue Component Updates

Filter selections update reactive state in Vue components. Computed properties automatically derive filtered data locally.

3

API Request

Frontend calls API endpoint via Axios with query parameters: GET /api/inventory?warehouse=Warehouse-A&category=Electronics

4

Backend Processing

FastAPI receives request, applies filter functions in order (warehouse → category → status), validates data with Pydantic models.

5

Data Retrieval

Backend filters in-memory data (loaded from JSON at startup), performs calculations (totals, averages, counts).

6

Response

Backend returns JSON response matching Pydantic response_model (type-safe serialization).

7

Frontend Rendering

Axios updates component state, Vue reactivity triggers computed properties, template re-renders with filtered data and visualizations.

API Endpoints

Base URL: http://localhost:8001/api

Method Endpoint Description
GET /inventory Get inventory items (filters: warehouse, category)
GET /inventory/{id} Get specific inventory item
GET /orders Get orders (filters: warehouse, category, status, month)
GET /orders/{id} Get specific order
GET /demand Get demand forecasts
GET /backlog Get backlog items with purchase order status
GET /dashboard/summary Get dashboard summary statistics (all filters)
GET /spending/summary Get spending summary statistics
GET /spending/monthly Get monthly spending breakdown
GET /spending/categories Get spending by category
GET /spending/transactions Get recent transactions
GET /reports/quarterly Get quarterly performance reports
GET /reports/monthly-trends Get month-over-month trends

Core Data Models

InventoryItem

Represents a product in inventory

• id, sku, name

• category, warehouse

• quantity_on_hand

• reorder_point, unit_cost

Order

Represents a customer order

• id, order_number, customer

• items (list of products)

• status, order_date

• total_value

DemandForecast

Predicted demand for items

• item_sku, item_name

• current_demand

• forecasted_demand

• trend, period

BacklogItem

Order items pending fulfillment

• order_id, item_sku

• quantity_needed

• quantity_available

• priority, days_delayed

PurchaseOrder

Supplier purchase orders

• backlog_item_id

• supplier_name

• quantity, unit_cost

• status, delivery date

Spending

Financial metrics and costs

• total_spending

• monthly breakdown

• by_category

• transactions

Development Guidelines

✅ Do's

✓ Use unique keys in v-for

✓ Validate dates before parsing

✓ Update Pydantic models

✓ Use Composition API

✓ Centralize API calls

✓ Add meaningful comments

❌ Don'ts

✗ Use array index as key

✗ Mutate props directly

✗ Skip validation

✗ Mix Options + Composition API

✗ Ignore error states

✗ Add unnecessary comments

🚀 Performance Tips

• Use computed properties

• v-show for frequent toggles

• Lazy load components

• Debounce API calls

• Cache request results

• Monitor bundle size
